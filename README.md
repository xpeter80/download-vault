# 下载保险箱

正式入口：**https://h.xpeter.net:6443/downloads/**。手机和电脑都使用这个地址，无需让 Mac 保持开机。

登录修复入口：**https://h.xpeter.net:6443/downloads/login**。此入口会携带返回地址，验证后直接回到保险箱；请不要收藏通用的 `/auth/login` 页面（其默认目的地是账号中心）。

使用现有 Nova 账号登录，仅 `verify-owner` 验证通过的老板账号有权限。NAS SSH 密码不作为 Web 登录密码。

## 下载加速（1.9.1）

手机右上角「⋯ → 设置 → 下载加速」。默认推荐：5 个并发、下载不限速、总上传 50K、不做种、64MB 缓存、100 个 BT 节点、直链每服务器 8 个连接，DHT 与节点交换开启。

内置 ngosang trackers_best 和 XIU2 best 两个公共 Tracker 来源，每天由 NAS 后台刷新，去重合并并保留种子自带 Tracker；无需保持浏览器打开。单来源失败可降级，全部失败保留旧列表并每小时重试。页面提供立即同步、最后成功时间、地址数量和失败提示。自定义地址仅在高级设置里提供，用于公共 BT 资源。

设置保存到 SQLite，运行参数通过 RPC 应用，宿主固定白名单桥接将配置原子写入 aria2.conf。磁盘缓存、DHT 等需要重启的选项会明确提示，并提供重启下载器入口。关闭自动更新不会清空已有列表。恢复推荐值需保存后生效，不会自动重启 NAS。

## 手机端使用（1.9.0）

- 底部为探索、下载、保险箱。右上角“⋯”进入设置、下载异常处理和文件历史。
- 下载默认显示当前任务，点击“＋ 添加”粘贴直链或磁力，默认隐藏，可选择标签；关闭浏览器后 NAS 继续下载。
- 保险箱按创建年月展示，点月份查看文件。点击“选择”多选月份或文件，底部出现公开、移回及更多操作；支持全选未公开。
- 文件名点开详情，可管理标签、查看来源、公开/移回和删除。收藏按钮常驻，收藏文件受删除保护。
- “筛选”集中月份、区域、类型、排序和实时标签搜索。更多菜单提供历史、操作记录、全部移回、按月份公开及清理当前筛选的非收藏文件。永久删除前始终预览。
- 公开或移回完成后，10 分钟内显示“撤回”，通过正常状态检查将本批文件移回原区域。
- 探索输入网址浏览原站或输入关键词搜索；搜索条件包含最多 4 层深度、资源发布日期和历史增量探索。浏览页底部的“发现资源”展开下载结果，支持类型过滤。
- 原站禁止嵌入、需登录或动态交互的网站可能无法读取；可独立打开、切换阅读版或粘贴新页面网址。嵌入页内部跳转不能同步识别。HLS/DASH 为清单，本版不自动合并视频。
- 下载异常处理先检查残留，再考虑重启下载器或 NAS。正在下载、等待、暂停、做种的真实文件受保护，整机重启需明确确认。

根目录 `/home/nas3/download/nova-vault`：`.vault` 隐藏、`visible` 普通可见、`temporary` 临时公开。新增文件按年月归档，旧路径兼容。网页登录使用 Nova 老板账号，NAS SSH 密码不作为 Web 密码。

详见 [手机端改版](手机端改版.md)。

## 运行结构

- `app/server.py`：Python 3.12 标准库 HTTP API、SQLite、Aria2 RPC、单文件操作队列。
- `app/static/`：手机优先前端，无第三方 CDN。
- `tests/test_vault.py`：文件保护、冲突、幂等、恢复、鉴权和来源检查。
- `tests/nas_acceptance.py`：真实 Aria2 下载与 SHA-256、公开、归位、收藏保护验收。
- `tests/preview_server.py`：仅回环地址的 UI 测试夹具，不进入正式镜像。
- `deploy/run.sh`：正式容器启动配置。
- `部署及验收.md`：当前部署、验证范围和回滚方法。

本地测试：`python3 -m unittest discover -s tests -v`。镜像内运行 Python 3.12；本地测试支持 Python 3.9+。生产文件移动使用 Linux `renameat2(RENAME_NOREPLACE)`，不覆盖目标文件。

## 当前边界

- 只管理本应用新增的下载，不自动接管原有 AriaNg 下载或 NAS 存量文件。
- 支持 HTTP/HTTPS 直链和标准 BTIH 磁力链接；不解析网盘、视频网站网页，不提供种子上传、播放或手机取回文件。
- 本应用新建 BT 任务设置 `seed-time=0`，完成后不持续做种，以便文件归档和移动；原有 Aria2 全局设置不变。
- HTTP 链接最初解析时拒绝内网地址，但复用的 Aria2 负责后续重定向、DNS 和 BT 网络；此版本不是供不可信用户使用的下载代理。只向现有 owner 账号开放。
- 与 AriaNg 共用执行器，移动前会检查活动和等待任务，但不能锁住外部 AriaNg 的并发操作。不要在 AriaNg 中重新启动正在本应用整理的任务。
- 同一文件系统内移动；跨盘迁移不在此版本范围。根目录和现有文件的迁移需管理员处理。
- 授权检查最长缓存 30 秒；身份服务不可用且缓存过期时拒绝访问。

## 已下载提醒（1.1.1）

探索候选链接会标注以前的下载日期、任务状态和文件所在区域；管理文件清理后仍保留下载记录。探索与手动粘贴下载遇到重复资源时，须选择“仍然下载”才新建任务。

按完整直链匹配（保留查询参数），磁力按 BTIH 资源哈希匹配，忽略名称和 tracker 差异。不同直链即使内容相同也不能保证识别；仅覆盖本应用的任务记录，不扫描 AriaNg 历史。

## 关键词自动探索（1.2.0）

进入“探索 → 关键词自动探索”，输入目标网站和关键词。应用依据站点公开的搜索表单、OpenSearch、搜索模板或脚本中的明确请求发现 GET 搜索入口；也可在高级选项提供带 `{query}` 的搜索 URL/API。

按“搜索结果 → 详情 → 播放页”最多深入两层，自动识别媒体文件、HLS/DASH 地址、直链和磁力，并验证媒体响应。任务在 NAS 后台运行，可停止，最近 30 条任务记录可再次打开。“探索过程”显示入口识别依据、访问路径和失败原因；下载时保留原有隐藏选择与重复提醒。

本版是公开页面和数据的通用解析器，不是运行 JavaScript 的远程浏览器。登录、验证码、POST 搜索、动态签名和 blob 视频可能无法识别。HLS/DASH 可发现和复制播放地址，暂不自动合并分片或处理 DRM。只有已验证为文件的地址和合法磁力展示 NAS 下载按钮。

详细设计与限制见 [自动探索设计.md](自动探索设计.md)。

## 1.9.2 移回修复

Aria2 force-save 固定关闭：仅未完成下载进入重启会话，已完成/已取消任务不再因重启重下。设置更新只对发生变化的任务参数发起修改，避免无必要的任务重启。失败操作持续显示原因，不再十分钟后消失。现有冲突修复保留原文件，重新下载的副本隔离到 `.recovery`，不覆盖、不删除。
